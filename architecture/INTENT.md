# mytripo_public INTENT

> 제품 수준의 현재 상태 문서다. 날짜·경위·이력은 쓰지 않는다. 결정의 정본은 `decisions/` 다.

mytripo_public 은 사진이나 생성한 턴어라운드 시트로 게임에 쓸 메시를 만드는 macOS 데스크톱 앱이다. 형태는 로컬 모델이 만들고, 앱은 그 메시와 함께 로우폴리 판을 낸다. 사람형은 기준 마네킹(Universal Animation Library, CC0)과 같은 뼈대를 넣은 판도 낸다. 앱은 Rust 실행 파일 하나와, 따로 설치하는 로컬 모델 환경이다. AI 는 사용자가 이미 로그인한 `codex`·`claude` CLI 의 구독으로 부른다.

## 문제
3D 아트디렉터와 1인 게임 개발자는 레퍼런스 사진을 보고 로우폴리 블록아웃을 손으로 만든다. Tripo 같은 서비스는 따로 결제해야 하고, 결과가 촘촘한 메시라서 로우폴리로 쓰려면 다시 손봐야 한다. 이미 쓰는 ChatGPT·Claude 구독만으로 사진에서 바로 로우폴리를 얻는 도구가 없다.

## 기대 결과
- 앱을 실행하면 창이 사진을 넣으라고 안내한다.
- 사용자는 사진 1~3장을 창에 끌어 놓는다. 로우폴리가 만들어진다. 다른 조작은 필요 없다.
- 사진은 초록 또는 흰색 단색 배경이다. 앱이 로컬에서 배경을 지운다.
- AI 가 사진마다 앞·옆·뒤를 판별하고, 창은 사진을 앞·옆·뒤 칸 3개에 보인다. 사용자가 사진을 다른 칸으로 옮기면 메시를 다시 만든다.
- 사용자는 사진 대신 글 설명과 참고 사진으로 시트 생성을 지시할 수 있다. codex 가 앞·옆·뒤·위가 한 장에 든 턴어라운드 시트를 그린다. 끌어 놓은 사진의 배경이 단색이 아니면 앱은 그 사진을 참고 사진으로 삼아 시트 생성을 권한다.
- 시트는 사용자가 적은 대상을 그대로 그린다.
- 시트의 인물은 최소 6등신이다.
- 시트의 인물은 장비를 입힐 기본 몸이다. 옷, 신발, 모자, 무기, 가방 없이 회색 속옷만 입는다. 장비는 게임 안에서 따로 입힌다.
- 시트의 인물은 손가락을 모은 손으로 그려지고, 메시의 손끝은 뭉툭하다.
- 사용자는 시트를 보고 진행, 수정 지시, 다시 생성 중 하나를 고른다. 진행하면 앱이 시트를 칸으로 잘라 메시를 만든다.
- 사람형은 로컬 모델(TRELLIS.2)이 앞 칸 사진으로 형태를 만든다. 앱은 로우폴리 판에 뼈 65개를 넣어 `<yyyyMMdd-HHmmss>.rig.glb` 로 저장한다. 뼈의 이름, 구조, rest 방향은 기준 마네킹과 같아서 애니메이션 라이브러리의 동작 클립이 그대로 재생된다. rest 포즈는 T포즈다.
- 사람이 아닌 대상(사물, 탈것)은 로컬 모델(TRELLIS.2)이 옆 칸 사진으로 형태를 만든다. 앱은 그 메시를 시트의 칸에 맞춘다. 오목한 곳과 가려진 곳은 모델이 추정한다. 한 번에 3~10분이 걸린다.
- 가려진 쪽의 형태가 마음에 들지 않으면 사용자는 "다른 형태로 다시 만들기" 를 누른다. 앱은 모델의 seed 를 바꿔 모델만 다시 돌린다(3~10분, 구독 호출 없음).
- 앱은 그 메시에서 Blender 로 로우폴리 판(삼각형 5000 이하)을 함께 만들고 `<yyyyMMdd-HHmmss>.low.glb` 로 저장한다. 사용자는 미리보기를 촘촘한 메시와 로우폴리 판 사이에서 바꾼다.
- 로컬 모델이 설치되지 않았으면 사람형은 단면 고리 로프트로 만들고, 사물은 claude 가 부품을 나누고, 앱은 부품마다 옆(가로 막대는 앞) 윤곽을 밀어내고 두께를 앞·위 실루엣에 맞춘다.
- 앱은 생성한 시트를 `~/Documents/mytripo_public/<yyyyMMdd-HHmmss>-sheet.png` 로 저장한다.
- 사용자는 결과를 마우스 드래그로 돌려 보고 휠로 확대한다.
- Cmd+N 은 현재 작업을 닫고 사진 넣기 화면으로 돌아간다. 상단의 뒤로 버튼은 앞 화면(시트 수정 중이면 결과, 그 밖에는 사진 넣기 화면)으로 돌아간다.
- 사진 넣기 화면은 이전 작업 목록을 보인다. 사용자는 이전 작업을 열거나(저장된 결과, 구독 호출 없음) 같은 입력으로 다시 만든다(claude 1회).
- 결과 파일은 `.glb` 다. Blender 의 File > Import > glTF 2.0 으로 열린다.
- 앱은 생성 즉시 결과를 `~/Documents/mytripo_public/<yyyyMMdd-HHmmss>.glb` 로 저장하고 화면에 저장 경로를 보인다.
- 결과 메시는 색이 없다. 회색 재질 하나만 쓴다. 미리보기는 밝은 배경에 회색으로 보인다. 로컬 모델의 메시는 정점 법선이 있어서 매끈한 음영으로 보인다.
- 결과 메시는 Y-up, 미터 단위, 발바닥 원점, 메시 1개, 재질 1개다.
- 결과 메시를 앞·옆·뒤(시트에 위 칸이 있으면 위까지)로 직교 렌더한 실루엣과 입력의 실루엣이 IoU 0.9 이상으로 겹친다. 로컬 모델의 메시는 사람은 앞·뒤 칸에서 0.9 이상, 옆 칸에서 0.7 이상이다. 사물은 옆 칸에서 0.85 이상, 나머지 칸에서 0.7 이상이다. 부품 조립은 0.85 이상이다.
- 부품 조립의 메시에서 바퀴는 차체와 떨어진 회전체이고, 타이어와 안으로 들어간 허브가 보인다.
- 결과 메시는 삼각형 예산 안에 든다. 예산은 2000 이고, 로컬 모델의 메시는 50000, 그 로우폴리 판은 5000 이다.
- 사용자는 턴어라운드 시트와 자세 설명으로 자세 시트 생성을 지시할 수 있다. codex 가 같은 인물이 그 자세를 한 모습을 앞·옆·3/4 시점으로 한 장에 그리고, 앱은 `<yyyyMMdd-HHmmss>-pose.png` 로 저장한다. 손은 자세에 맞는 모양으로 그린다. 이 그림은 동작의 참고 그림이고 메시 입력이 아니다.
- 에이전트는 사람형 `.rig.glb` 에 자세 JSON 의 동작(전환 · 유지 클립)을 넣어 `.glb` 로 낸다. 발은 바닥에 붙어 있고, 클립 사이와 루프 끝은 이어진다. 결과는 숫자 검사와 비교 시트로 확인한다.
- 로프트로 만든 사람형 메시는 관절 자리에 edge loop 가 있다. 로컬 모델로 만든 사람형은 edge loop 가 없고, 뼈대에 자동 가중치로 붙는다.

## 영향 범위
- 사용자: 앱을 실행하는 본인 1명. macOS.
- 시스템: Rust 실행 파일 하나가 창, 3D 미리보기, 사람형 메시 생성, 모델 메시 맞추기, 파일 출력을 맡는다.
- 외부 연동: 로그인된 `codex` CLI(ChatGPT 구독)와 `claude` CLI(Claude 구독), 로컬 모델 환경(`~/Documents/mytripo_public/model`, `scripts/setup_model.sh` 가 설치한다), Blender(로우폴리 판). 앱은 넷을 하위 프로세스로 실행한다.
- 출력: `.glb` 파일. Blender.

## 제약
- 앱은 로그인된 CLI 의 세션만 쓴다. 앱은 API 키를 받지 않고 저장하지 않는다.
- 구독에는 사진을 3D 메시로 바꾸는 모델이 없다. codex 는 턴어라운드 시트의 생성과 수정만, claude 는 구조 읽기(앞·옆·뒤, 사람 여부, 부위, 관절점, 사물의 부품 상자)만 맡는다. 형태는 로컬 모델이 만든다. Rust 는 그 메시를 칸에 맞추고, 모델이 없을 때의 메시를 계산한다.
- 로컬 모델은 사진 한 장만 본다(사물은 옆 칸, 사람은 앞 칸). 앞·뒤·위에서 본 형태는 모델의 추정이라서 시트의 그 칸과 다를 수 있다.
- 이 저장소는 로컬 모델 TRELLIS.2 의 코드와 가중치를 담지 않는다. 설치 스크립트가 원 저장소에서 받는다. 이미지 인코더 DINOv3 의 가중치는 Hugging Face 접근 승인이 필요하다. [0006](decisions/0006-learned-model-for-objects.md)
- 구조 읽기는 메시를 만드는 입력마다 1회다. 시트 생성, 시트 수정, 자세 시트 생성은 사용자가 지시할 때만 1회씩 부른다. 구독의 메시지 한도를 아낀다.
- 사람형과 부품 조립에서 사진과 시트는 실루엣만 준다. 오목한 곳, 가려진 곳, 손가락, 눈·입, 옷 주름 같은 세부는 만들지 않는다. 실루엣 교집합은 같은 높이에서 가장 넓은 부분의 폭을 피사체의 깊이 전체로 퍼뜨린다(예: 핸들 아래의 바퀴가 두꺼워진다).
- 첫 버전은 macOS 만 지원한다.
- 앱은 본인 로그인으로 도는 도구다. 구독 CLI 의 약관 안에서 쓴다.

## 결정
- 로우폴리는 실루엣 단면을 쌓아 만든다. 촘촘한 메시를 줄여서 만들지 않는다. [0001](decisions/0001-loft-from-silhouettes.md)
- codex 가 턴어라운드 시트를 만들고 claude 가 구조를 읽는다. [0002](decisions/0002-turnaround-sheet.md)
- 사람이 아닌 대상은 앞·옆·뒤·위 실루엣의 교집합(visual hull)으로 만든다. [0003](decisions/0003-visual-hull-for-objects.md)
- 결과는 색 없는 회색 메시다. [0004](decisions/0004-gray-assets.md)
- 사람이 아닌 대상은 부품으로 조립한다. 부품 목록이 없으면 0003 을 쓴다. [0005](decisions/0005-objects-from-parts.md)
- 로컬 모델(TRELLIS.2)이 설치되어 있으면 형태는 그 모델로 만든다. [0006](decisions/0006-learned-model-for-objects.md)
- 모델 메시의 로우폴리 판은 Blender 를 창 없이 돌려 만든다. [0007](decisions/0007-blender-lowpoly.md)
- 사람형도 로컬 모델로 만들고 기준 마네킹의 뼈대를 넣는다. [0008](decisions/0008-human-model-with-mannequin-skeleton.md)
- 동작은 자세 JSON 과 Blender 스크립트로 만든다. [0009](decisions/0009-motion-from-pose-json.md)

## 열린 질문
- 사람 사진의 포즈 조건. A포즈나 T포즈를 요구할지.
- 사용자가 삼각형 예산을 바꾸는 UI 를 둘지.
- 사물의 움직이는 부품(바퀴)을 따로 떼어 낼지.
