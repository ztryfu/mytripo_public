# 0006 형태는 로컬 모델 TRELLIS.2 로 만든다

## 결정
로컬 모델 환경이 설치되어 있으면 앱은 부품 조립(0005)과 로프트(0001) 대신 로컬 image-to-3D 모델 TRELLIS.2 를 쓴다. 앱은 사진 한 장(사물은 옆 칸, 사람은 앞 칸)을 모델에 넘긴다. 설정은 `1024_cascade` 와 dual contouring remesh 다. 모델이 낸 메시는 같은 자리의 정점을 합치고, 떠 있는 작은 조각을 버리고, 삼각형 50000 개까지 줄이고, 시트의 칸에 맞춘다. 방향은 수직축 둘레의 네 방향과 좌우 뒤집기 가운데 칸의 실루엣과 가장 많이 겹치는 것을 고른다. 키는 구조 읽기의 값에, 길이와 폭은 칸에 맞춘다. 메시는 정점 법선을 가진다.

모델 환경이 없으면 사물은 0005, 사람형은 0001 을 쓴다.

## 근거
- 부품 조립은 윤곽을 평평한 두 끝면 사이로 밀어낸 덩어리다. 오목한 곳(엔진 틈, 프레임, 바퀴살)과 가려진 곳을 만들지 못한다.
- 3D 데이터로 학습한 모델은 그런 곳을 추정해서 채운다. 구독(codex, claude)에는 그런 모델이 없다.
- TRELLIS.2 의 코드와 가중치는 MIT 다.
- 같은 시트(SF 오토바이, seed 42)로 설정을 비교했다. 실루엣 IoU(앞/옆/뒤/위)는 `512` 0.788/0.880/0.778/0.749, `1024_cascade` 0.793/0.888/0.775/0.746, `1024_cascade` + remesh 0.765/0.893/0.748/0.754 였다. 숫자는 비슷하지만 `512` 는 얇은 표면(앞 페어링, 흙받이)이 구멍 난 조각으로 깨졌고, remesh 를 켠 판이 표면이 이어지고 엔진과 배기관이 가장 또렷했다.
- 생성 시간(M 시리즈 Mac, 모델만): 오토바이 `512` 159초, `1024_cascade` + remesh 445초 + 정리 94초. 사람 161초 + 23초, 등불 196초 + 35초. 불러오기 120~180초가 따로 든다.

## 버린 안
- 부품 조립을 고치는 방식(끝면 평면 맞추기, 테두리 깎기, 원통 부품): 각진 정도는 줄지만 오목한 곳과 가려진 곳은 여전히 없다.
- 지역 제한이 있는 라이선스의 모델: 공개 저장소에서 쓸 수 없다.
- 유료 API: API 키와 결제가 필요하다.

## 결과
- 모델은 앱 밖의 Python 환경이다(`scripts/setup_model.sh`, 환경 약 2 GB, 가중치 약 16 GB). 앱은 `codex`·`claude` 처럼 하위 프로세스로 부른다.
- 설치는 `shivampkumar/trellis-mac`(MIT)의 설치 스크립트와 패치를 쓴다. Metal 백엔드(`mtlgemm` `mtlmesh` `mtlbvh` `mtldiffrast`, `o_voxel`)를 빌드하므로 Xcode Metal 툴체인이 필요하다. 설치 스크립트는 생성을 확인한 커밋과 패키지 버전으로 고정한다.
- 이미지 인코더 DINOv3 의 가중치는 Hugging Face 에서 접근 승인을 받아야 내려받는다(Meta DINOv3 License).
- 배경 제거 모델(RMBG-2.0, CC BY-NC 4.0)은 내려받지 않는다. 앱이 배경을 지운 RGBA 를 넘긴다.
- 대상 하나에 3~10분이 걸린다. 구독 호출 수는 그대로다.
- 모델 메시는 삼각형 50000 개까지다. 로우폴리가 아니다. 토폴로지는 불규칙하다.
- 모델은 한 칸만 본다. 사물의 옆 IoU 는 0.85 이상이고, 앞·뒤·위는 모델이 추정한 형태라서 0.7~0.8 이다.
- TRELLIS.2 의 메시는 열린 얇은 판이 많다. 로우폴리 단계가 이를 다룬다(0007).
- seed 는 42 에서 시작하고 사용자가 버튼으로 올린다. MPS 에서 같은 seed 가 같은 메시를 내는지는 확인하지 않았다.
- `MYTRIPO_PUBLIC_PIPELINE=512` 로 빠른 설정을, `MYTRIPO_PUBLIC_REMESH=0` 으로 remesh 없는 설정을 고른다.
