# 0009 동작은 자세 JSON 과 Blender 스크립트로 만든다

## 결정
사람형 rig 의 동작은 앱 밖의 `scripts/blender_anim.py` 가 만든다. 입력은 자세 JSON 이다. 자세 JSON 은 이름 있는 자세(뼈별 회전, 골반 이동, 발 자리, 손가락 굽힘)와 클립(두 자세 사이의 전환, 한 자세의 유지와 흔들림)을 적는다. 출력은 클립마다 glTF 애니메이션 하나가 든 `.glb` 다. 같은 스크립트가 결과를 숫자로 검사하고 비교 시트를 그린다.

## 근거
- 공격 직전 자세를 시험했다. 에이전트가 bpy 를 매번 새로 짜자 축 부호, 무릎 방향, 두 발이 함께 뜨는 것, IK 의 이음새, fps, 뼈 표시용 메시에서 실수가 6건 나왔다. 같은 스크립트를 다시 쓴 두 번째 시험에서는 0건이었다.
- 자세가 맞는지는 숫자로 판정할 수 없다. 참고 이미지가 없을 때 에이전트의 기억은 틀렸다. 그래서 스크립트는 시트와 참고 이미지 비교를 그리고, 판단은 그림을 보는 쪽(에이전트, 사용자)에 남긴다.
- 뼈 이름과 rest 방향이 기준 마네킹과 같으므로(0008) 이 동작은 라이브러리의 동작 클립과 같은 방식으로 재생된다.

## 버린 안
- 앱(Rust) 안의 동작 편집 UI: 자세를 고치는 일은 에이전트가 숫자로 하는 편이 빠르고, 앱은 메시를 만드는 데 집중한다.
- 오일러 값의 선형 보간: 두 자세 사이에서 팔이 어색한 경로로 돌았다. 회전은 slerp 로 섞는다.

## 결과
- 팔을 가슴 앞으로 어깨 높이까지 들고 몸통을 숙여 돌린 자세에서 옆에서 보면 어깨 뒤가 솟아 보인다. 솟은 정점은 `upperarm_r` 가 주로 잡는 어깨 뒤 정점이고, `spine_03` 만 따라갔을 자리에서 2~5 cm 벗어난다. weight 를 안쪽으로 줄이는 시험은 모양을 바꾸지 못했고, `clavicle` 에 앞으로 모으는 회전을 나누자(예: `clavicle_r` z 22, `upperarm_r` z 62 → 40) 눈에 띄게 줄었다. 그래서 rig 가 아니라 자세의 문제로 본다. 이 스크립트의 검사는 그것을 잡지 못한다.
- 손은 손가락을 모은 덩어리라서 손가락을 굽히면 주먹처럼 보인다.
